### scan4seq family (gc-get.c:102-553) — VERDICT: REFUTED for NEON (V-002 critical); x86 variants HELD (ATTACKED→held)

**NEON (gc-get.c:449-498, return at :469) — REFUTED, critical.** The mask from `diffcmp2mask_neon` packs each matching lane as a **16-bit field** (`vmovn_u32` → u16x4, little-endian u64: lane b at bits [16b,16b+15]). `clz64(mask) = 48-16b`; the correct offset to lane b's element `(range-3)+b` is `-(clz>>4)`. The code does `-(clz_uintptr(mask) >> sizeof(size_t)/4)` = `>>2`, returning `range + 4b - 12` — correct only for b=3, wrong (and walks outside the loaded group, down to `range-12`) for b∈{0,1,2}. Differential harness (faithful per-instruction emulation of vmovn + LE layout, control flow replicated exactly; /tmp/gcaudit/scan4seq_diff.c): **~4% of random *valid, strictly-descending* PNLs diverge from the fallback** (10,361/300k even without forced runs; 17,708/300k run-heavy). Minimal counterexample, no crafted data needed:
- `repnl = [10, 6, 5, 1]` (valid descending, len=4), `num=2` (seq=1). Reference: position 3 (pnl[2]−pnl[3]=6−5=1), pgno=5, cuts {6,5} — correct. NEON: tail path, mask=0x0000FFFF00000000 (lane 2), clz=16, `>>2`=4 → returns **position 0** → `pgno = pnl[0]` (the *list length* read as a page number), and the cut loop then writes `target[-num]` starting at `target=pnl+1` → writes **`pnl[-1]` (the alloclen field) and below** → heap underflow write + garbage cut. Other observed failures return NULL where a run exists, or arbitrary wrong positions (e.g. `len=7 seq=1` returns idx 3 instead of 6).
- Reachability: any aarch64 build (scan4seq_resolver picks NEON); the debug-only `ASSERT(target == scan4range_checker(...))` in `gc_repnl_get_sequence` masks it in debug CI; release silently mis-cuts `wr.repnl` → wrong pages allocated/returned → DB corruption. Inherited from upstream: git history shows only `__builtin_clzl(mask)` → `clz_uintptr(mask)` renaming, same wrong shift.

**sse2/avx2/avx512bw/fallback — HELD.** 800k randomized differential cases (incl. run-heavy lists and alternating page-safe/unsafe tails forcing the `sse2avx`/`avx2` bridge and scalar paths): zero divergence. Analytic verification: clz biases 28/24/16 yield `(range-3/7/15)+lane` correctly; OOB tolerance is exact — lowest byte read is `(range+offset)*4 − {12,28,60}` vs page-safe margins `0xff0/0xfe0/0xfc0` = {16,32,64} bytes (the "-15/-31/-63" comments are element-count conservative roundings). Invalid lanes (positions < seq+1, i.e. reads of `pnl[0]`, `pnl[-1]`, `pnl[-2]`) are never *selected*: main-loop bodies execute only at `range ≥ detent+width` (all lanes ≥ detent+1 — the do-while decrements inside the body); the `extra` masks (`0xF<<extra`, `0xFF<<extra`, `0xFFFF<<extra`, `~0<<(extra*16)`) keep only lanes ≥ detent+1; the exact-multiple case (`range==detent`) discards the last block's invalid lanes via the early `return nullptr`. The `extra ASSERT (0<extra<width)` invariants hold by loop-exit construction (extra = detent+width−range ∈ [1,width−1]). The `goto found` reuse after tail masking recomputes with the same correct formula. No PNL found where x86 SIMD returns a different element than fallback.

### gc_repnl_get_sequence cut/paste (gc-get.c:717-772) — HELD (ATTACKED→held)
Cut loop: `for (end = pnl+len; ++target <= end;) target[-num] = *target`. Boundary `num=len`: `target = pnl+len` → `++target > end` → zero iterations, size→0 ✓. `num=len-1`: one move of `pnl[len]→pnl[1]` ✓. Minimum legal `target0 = num` (detent=pnl+seq, first checked position seq+1) → first write index `target0+1-num = 1`, never negative ✓. Replication harness (cut_paste_test.c): 8 boundary cases + 200k random sorted lists — all post-cut invariants hold, incl. full-span and near-full-span cuts. `ALLOC_EXACTLY` branches compiled out (`#if 0`, gc.h:61). The scalar `scan4range_checker` agrees with the found position on sorted data (part of the harness; on aarch64 the *neon* result breaks this assert — V-002).

### gc_alloc_ex FSM (gc-get.c:959-1527) — HELD (ATTACKED→held)
Full goto enumeration: `retry_gc_refresh_detent → retry_gc_have_detent → next_gc ⇄ (LIFO PREV / FIFO NEXT / coalesce-continue / continue-search) → scan ⇄ depleted_gc → {done | no_gc} → done/fail`, plus `reserve_done` (inside done's else-branch) and fail.
- (a) No path returns a page twice: `done` has no backward edges; every `goto done` with `pgno` follows repnl consumption; reserve-flag paths land in the reserve branch which never calls `page_alloc_finalize`. The early `num>1` scan (996) and the SHOULD_SCAN scan (1143-1153) both `goto done` immediately after consumption.
- (b) Failure consistency: every `goto fail` passes through the refund+`pnl_check_allocated(repnl, first_unallocated-1)` epilogue (when !MDBX_TXN_ERROR); all partially-applied in-txn state rolls back on abort since GC record delete/rkl bookkeeping commits only with the txn. Quirk (benign): MDBX_CORRUPTED on an ALLOC_UNIMPORTANT reserve logs at DEBUG and does not set MDBX_TXN_ERROR — but the error propagates and the commit fails.
- (c) `!num` slot-request never allocates: RESERVE asserted (`num > 0 || ALLOC_RESERVE`), steady block skipped via `ALLOC_UNIMPORTANT==0` gate, tail-allocation `goto done` skipped via `!(flags & ALLOC_RESERVE)`, `no_gc` → NOTFOUND fail. All branches verified.
- (d) Steady wipe/sync table: wipe fires for `UTTERLY_NOSYNC && ((no autosync) || newnext ≥ steady.now)`; make-steady fires on unsynced-threshold, eoos-period, `newnext ≥ geo.upper`, or `(num==0 || newnext ≥ end_pgno) && no-autosync`; gated by `recent ≠ prefer_steady && prefer_steady.is_steady && detent == prefer_steady.txnid`. Each firing monotonically advances the troika → the retry loop strictly reduces work and terminates; `depleted_gc → scan → depleted_gc` second pass falls through with SHOULD_SCAN cleared. The `rdt_refresh_flag`/kick-laggards retries are bounded by forward-only detent movement.

### gc_store_retired, BIGFOOT path (gc-put.c:363-435) — VERDICT: REFUTED, FIFO mode (V-003 high)
`should_retry = retired_before != retired_after && chunk < retired_after` intends "retry unless the grown list still fits this one chunk". But when it *does* still fit (`retired_after ≤ chunk_hi = (left_before|3)`, only possible on the first chunk, `stored==0`), `chunk == retired_after > left_before` and the FIFO branch computes
```c
const size_t at = (is_lifo(txn) == MDBX_PNL_ASCENDING) ? left_before - chunk : ctx->retired_stored;
```
i.e. `at = left_before - chunk` **underflows**; `txn->wr.retired_pages + (size_t)at` wraps to `&retired[-k]`. Simulation with faithful line-by-line replication (/tmp/gcaudit/store_retired_sim.c, all 8 scenarios):
- `retired_before=8` (≢3 mod 4), `cursor_put` retires +1 → `at=-1`: `*begin=chunk` clobbers `pnl[-1]` (in-malloc, restored after), and the stored GC record becomes `[9][9][900..893][70000…]` — **element[1] = the PNL size field (9) read as a page number; the last real retired page (70000) is dropped** (leak). `pnl_check_lite` rejects this record on next read (LEAST 893 ≥ MOST 9) → MDBX_CORRUPTED, writers bricked.
- growth +2/+3 → `at=-2/-3`: `*begin = chunk` **writes OOB before the malloc block** (in-place restored, but transient heap underflow write), record contains `{junk, alloclen(1022), size(10|11), pages…}` → if 1022 < first_unallocated, `pnl_check_lite` **passes** → silent GC corruption: bogus pages 1022/10 recorded free, real pages dropped → later double-allocation of live pages.
- Trigger conditions: FIFO (default), BIGFOOT=1 (default), first chunk, growth g∈[1,3] with `retired_before ≢ 3 (mod 4)` (g=1), ≢2,3 (g=2), ≡0 (g=3), retired list ≤ goodchunk. The growth mechanism is real: `page_touch()` on a frozen page does `pnl_append(&txn->wr.retired_pages, …)` (page-ops.c:177), and `cursor_put` can reach frozen pages despite `gc_touch` pre-dirtying the path (e.g. split → `gc_alloc_single` → GC reclaim → record deletion → FREE_DBI rebalance touching frozen siblings). The non-BIGFOOT branch's own retry comment ("Retry if wr.retired_pages[] grew during the Put()") proves the authors observed such growth; the LIFO branch (`at = retired_stored = 0`) handles it *correctly* — only the stale-`left_before` FIFO formula is broken. Correct fix shape: use `retired_after - chunk` instead of `left_before - chunk`.

### gc_fill_returned (gc-put.c:1311-1415) — HELD (ATTACKED→held)
`factor = (surplus<<32)/return_reserved_hi < 2^32` strictly (surplus < hi since amount ≥ 1) ⇒ `hole = (chunk_hi*factor)>>32 < chunk_hi` ✓; `hole ≤ surplus` because `chunk_hi ≤ return_reserved_hi` ✓; `chunk ≤ left` trivially in the entered branch; `chunk -= 1` refinement guarded by `chunk > 1` and the remaining-surplus comparison (operands non-negative, no wrap). Extreme `surplus ≈ hi` (small amount): every slot still gets `chunk ≥ 1`; single-slot path guards `iov_len - bytes(amount) ≥ 2*ps → RESULT_TRUE` (retry). Comeback exhaustion → "reserve depleted" → MDBX_PROBLEM → txn fails cleanly (fail-safe). Surplus can only underflow on the final iteration and the wrapped value is dead. Precision check: `(left + surplus - chunk_hi) * factor >> 32` parses as intended (shift binds tighter than relational).

### gc_dense_solve / solve_recursive / consume_* (gc-put.c:612-753) — VERDICT: memory-HELD, liveness REFUTED (V-004 medium)
Memory safety: `consume_stack` terminates (every iteration decrements a counter or `end`); `consume_remaining`'s `solution[len-1]` at `len→0` is unreachable (factor ≥ 2 keeps len ≥ 1); the binary search strictly narrows; recursion depth ≤ hist.end ≤ 31 with ~144B frames ≈ 4.5KB stack — the "~4KB" claim holds.
**Liveness REFUTED**: `solve_recursive` uses a full recursive search as its binary-search predicate → work ≈ (log₂N)^H. Concrete input from randomized fuzzing of the faithful replication (solver_hang.c): hist = runs {len2×42, len7×143, len17×87, len18×17, len24×9} (end=24), `left_slots=1021`, `return_left=3557022` → **84,036,349 recursive calls (~45s at -O2) to return FALSE** — and that is a small shape; end→31 with thousands of slots scales combinatorially (effectively forever). Reachable: `gc_handle_dense` is the designed path for the legacy-huge-GC-records + id-deficit scenario (`dense_unfit > 0`); slots = `rkl_len(ready4reuse)` (hundreds realistic after a big drain), volume = drained repnl (millions). The hang sits inside one `gc_rerere` call, so the `ctx->loop > 42` bound never applies; the commit thread (writer mutex held) stalls with no timeout. Fail-safe w.r.t. correctness (eventually FALSE → fallback reservation loop; the built-in volume/items self-check catches wrong solutions as MDBX_PROBLEM), but the commit is denial-of-serviceable.

### gc_update loop bound (gc-put.c:1435-1545) — HELD (ATTACKED→held)
`loop` increments only when `first_unallocated` did not shrink; progress requires a strict decrease (bounded below by NUM_METAS via `txn_refund`, refund.c:173, which only pops `MOST == first_unallocated-1`). Every `goto retry`/`continue` either advances a monotone quantity (`retired_stored ↑` after store; `return_reserved_hi ↑` per `gc_reserve4return`; `reclaimed` rkl ↓ per clear) or increments the counter; reserves unwound at `retry` (`gc_clear_returned` zeroes lo/hi and recycles comeback→ready4reuse). No oscillation can evade the counter: any iteration without `first_unallocated` progress counts; >42 (12 debug) → MDBX_PROBLEM bailout (cursor unlinked, repnl cleared, commit fails cleanly). The `retry`-time `gc_clean_stored_retired` correctly resets `retired_stored=0` when it deletes stored records.

### page_alloc_finalize prefault batching (gc-get.c:819-881) — HELD with one benign quirk
`file_offset` is set only at `n==0` (run start) and advanced by exactly `MDBX_AUXILARY_IOV_MAX` pages per full flush; the tail flush uses the outstanding `n`. Quirk: an in-core page inside a run is skipped in the iov list but does not flush/reset the batch, so `pwritev` covers it contiguously — the pattern is written over an in-core page **of the just-allocated span** (safe: allocated pages are fully initialized by the writer before commit — the base allocation contract) and no page outside `[pgno, pgno+num)` is ever touched. Missed prefaults are perf-only. `stub_write_errdecide` (internals.h:768) currently returns the error unchanged → prefault/media failure fails the allocation and the txn — deliberate per issue #203, no silent drop. Partial-batch failure skips retrying that batch's pages but the txn aborts. The mincore cache feeding `env_is_page_incore` lives in shared lck memory and is raced non-atomically across processes — result only gates this optimization → benign.

### gc_merge_loose (gc-put.c:289-361) — HELD (ATTACKED→held)
Scratch `loose = repnl + alloclen − L − 1` occupies `[alloclen−L−1, alloclen−1]`; `pnl_need(2L+2)` guarantees `alloclen ≥ size+2L+2 > size+L+1` → no overlap with live `repnl[0..size]`; `pnl_merge` output writes `repnl[1..size+L] ≤ alloclen−L−1` (incl. both memcpy fast paths and the backward inner merge) → scratch never collides with repnl growth. Loose pgnos cannot duplicate repnl content (a repnl page leaves the list when allocated), so merge length is exact. The retired-append path `pnl_need(L)`s first; unsorted appends re-sorted in `gc_store_retired` (gc-put.c:382) before any consumer. Dirtylist filtering keeps `dl->sorted ≤ w` bookkeeping consistent (`sorted_out` counts only entries at or before the write index).

## Defenses that hold only under specific assumptions

1. **scan4seq correctness** holds only on x86 (sse2/avx2/avx512) or non-NEON ARM. On aarch64 the V-002 formula bug breaks it for valid data — no crafted input needed. (Upstream-inherited.)
2. **gc_store_retired BIGFOOT** correctness assumes `wr.retired_pages` does not grow during a chunk's `cursor_put(MDBX_RESERVE)` into the window `(left_before, left_before|3]`. `gc_touch` pre-dirtying the whole path makes this *usually* true, but reclaim-during-split and rebalance/merge of non-pre-touched frozen siblings can break it; LIFO mode (`MDBX_LIFORECLAIM`) is immune to V-003 by construction.
3. **Dense-mode commit termination** assumes hist diversity and slot counts stay small; no bound exists (V-004). Timely only for near-uniform histograms or tiny slots.
4. **"GC record valid iff order+duplicates OK"** holds only with `MDBX_VALIDATION` (pnl_check_full, O(n) order scan). The default release path checks bounds + first>last only (pnl_check_lite) plus the co-presence-only merge-length check — the crafted-disorder double-allocation scenario of V-022 is admitted by design ("a release build does not pay for crafted-data hardening", gc-get.c:934).
5. **page_alloc_finalize pattern-over-incore-page writes** are safe only under the allocation contract that the caller fully initializes all `num` allocated pages before commit (true today).
6. FIFO-mode store correctness additionally requires the trigger window of V-003 to be empty — it is not provably empty, only empirically rare.

## Explicitly attacked and not broken

`pnl_merge` P_INVALID sentinel (src_a exhaustion reads stop at `dst[0]`; reads stay within `[pnl−1, pnl+total]`); `pnl_check_lite` extremes gate; gc_alloc_ex steady wipe/sync termination; depleted→scan→depleted two-pass; `gc_clean_stored_retired` bigfoot decrement loop (no underflow, id ≥ 1); `gc_remove_rkl` NOTFOUND→ready4reuse recycling; `gc_search_holes` unsigned `--end ≥ begin` (terminates via `gc_push_sequel` RESULT_TRUE before wrap matters); `gc_reserve4return` oldest-slot runtime guard (PROBLEM, fail-safe); `gc_fill_returned` surplus/refinement asserts (all provable); `consume_stack/consume_remaining` termination and the benign `solution->end` clobber at the len→0 edge; `gc_update` 42-bound convergence; mincore cache arithmetic (`bit = i>>shift` ≤ 63 ✓) — its cross-process race is benign (optimization gate only); `gc_put_init` partial memset before `sequel` (no rkl zeroing bug — `rkl_init` runs after).

Test-coverage note: there are **no unit tests** for `scan4seq*` in `tests/` — a sorted-input differential test (fallback vs each SIMD variant) would have caught V-002 immediately; cheapest regression test to add.
