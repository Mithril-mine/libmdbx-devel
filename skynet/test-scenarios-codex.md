# Кодекс тестовых сценариев (test-scenarios codex)

> Стандарт качества для `skynet/test-scenarios.md` (SC-*) и его ревью.
> Сценарии — рабочий материал для тест-писателей (юнит-тесты 100–1000× быстрее
> smoke) и для пробников SystemTap/DTrace. Документ появился из требований
> владельца: сценарии создавались параллельно с факт-чеком без системного
> ревью; их много, поэтому нужны единые критерии.

## Цель сценария

Один сценарий = **одна проверяемая гипотеза** поведения libmdbx, выраженная
так, чтобы тест-писатель мог превратить её в быстрый юнит-тест, а
пробник-инженер — в точки встройки зондов.

## Обязательные поля (после ревью)

| Поле | Требование |
|---|---|
| `id` | уникальный `SC-N` (без дублей, порядок не важен) |
| `area` | одна из: core/api/cxx/txn/gc/dbi/cursor/dupsort/issues/platform |
| `hypothesis` | что именно проверяем (одно предложение) |
| `preconditions` | схема БД, размеры, кол-во записей, sync-mode, диск |
| `steps` | конкретные операции с точными API (`mdbx_env_set_geometry`, …) |
| `expectations` | измеримо: значения, счётчики, коды возврата, отсутствие падений |
| `probe_points` | **болевые точки**: функции/переменные для интроспекции и инъекции |
| `speed_class` | `unit` (<1с), `smoke` (<10–30с), `heavy` (>30с) — цель юнит |
| `sync_mode` | явный: nosync/nordmsync/durable — если durability не тестируется, брать `nosync`; диск: /dev/shm (Linux) / RAM-диск (Win) для heavy |
| `refs` | issues/ChangeLog/doxygen для обоснования |

## Критерии ревью (чеклист)

1. **Точность API** — каждое имя сверено с `mdbx.h`/`mdbx.h++` (не пересказ).
2. **Реализуемость** — сценарий можно собрать как юнит-тест, шаги детерминированы.
3. **Единственность** — не дублирует другой SC и не покрыто уже существующим
   юнит-тестом (сверка с `skynet/test-coverage.md`).
4. **Пробники** — `probe_points` указывают конкретные места (функция/строка/
   переменная) для интроспекции пути/ветвления, значений и инъекции ошибок
   (например `mdbx::alloc::source` вернуть `MDBX_MAP_FULL`).
5. **Скорость** — сценарий формулируется под `unit`/`smoke`; тяжёлые части —
   помечаются `heavy` и выносятся из обычных прогонов.
6. **Sync-mode и диск** — корректный выбор; durability упоминается только когда
   проверяется именно она.
7. **Нет маркетинга/общих рассуждений** — только проверяемое поведение.

## Вердикты ревью

- `ok` — можно передавать тест-писателю.
- `needs-work <пункты>` — список правок (какие поля/неточности).
- `rejected <причина>` — дубль, нереализуемо или вне scope.

## Процесс

- Координатор распределяет блоки сценариев по агентам (по мере занятости),
  сводит вердикты, отмечает в `skynet_tasks`/backlog (B16).
- Тест-писатель берёт сценарии со статусом `ok` (приоритет — с `speed_class=unit`
  и `probe_points`).
- Пробник-инженер (sysprobe) использует `probe_points` как контракт встройки.
- Неточности doxygen, найденные при ревью, фиксируются отдельно для docs
  (продолжение TASK-13/11).
