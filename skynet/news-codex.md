# news-codex — кодекс контента Telegram-канала @libmdbx

> Внутренний документ роя. Определяет, что и как публикуется в Telegram-канале
> проекта libmdbx (@libmdbx): темы, форматы, источники, запреты и чек-лист.
> Публикация выполняется мостом из TASK-32 (ветка `skynet-news`, GitHub CI).
> Черновики живут в `${SKYNET_ROOT}/.skynet/news/drafts/` (вне git);
> готовые к публикации драфты коммитятся в `skynet-news/drafts/`.

## 1. Цель

Регулярно (1 пост в 2–3 дня, 11:00–14:00 МСК) сообщать сообществу о прогрессе
открытого проекта libmdbx и о том, как рой ускоряет этот прогресс — без
раскрытия внутренних механизмов, метрик эффективности и чувствительных данных.

## 2. Требования владельца (verbatim)

### Открытое ПО (libmdbx)
- Подсвечивать: коммиты, новые модули, улучшения UX/API, багфиксы, рост покрытия
  тестами, вклад сообщества — **без раскрытия внутренних метрик эффективности
  команды**.
- Упоминать PR и issues публичного репозитория только ссылками на открытые
  тикеты/мерджи (без внутренних обсуждений).

### Закрытая часть (совершенствование роя и libmdbx/tests)
- Общие направления улучшений («повышена стабильность оркестрации», «сокращено
  время планирования задач», «улучшена интерпретируемость решений») — **без
  деталей архитектуры, проприетарных эвристик и фрагментов кода**.

### Синергия
- Как рой ускоряет работу над открытым продуктом («автоматизирована генерация
  тестов для нового модуля», «роем проведена классификация тикетов по
  приоритету») — **без раскрытия пайплайнов и чувствительных данных**.

### Форматы
- Заголовок-крючок ≤60 символов; 3–5 тезисов буллитами; 1 инсайт в конце
  (общий принцип, не секрет); длина поста ≤400 символов.
- Ровно один CTA на выбор:
  «Поделитесь мнением о новой фиче» / «Поставьте реакцию, если тема полезна» /
  «Предложите идею для следующего улучшения» / «Посмотрите PR по ссылке».

## 3. Запрещено публиковать

- Детали реализации закрытых компонентов роя, проприетарные алгоритмы,
  внутренние эвристики, уникальные формулы.
- Фрагменты кода, логи, дампы, конфиги, примеры запросов/ответов, могущие
  раскрыть внутреннюю логику или уязвимости.
- Ссылки на внутренние репозитории, CI/CD-пайплайны, доступы, ключи, токены.
- Персональные данные, роли, должности, контакты, внутренние обсуждения
  по тикетам.
- Финансовые и коммерческие метрики, планы монетизации, условия партнёрств.

## 4. Шаблон поста

```
Заголовок: «[Компонент/Практика] — прогресс за период»   (≤60 симв.)
Тезисы:   • Что стабилизировано/внедрено в открытом коде
          • Как рой помог ускорить/улучшить работу
          • Что это даёт пользователям/сообществу
Вывод:    «Следующий шаг — …»
CTA:      один из списка §2
```

## 5. Frontmatter драфта (формат YAML)

```yaml
---
id: <slug>            # уникальный id поста
title: <строка>       # заголовок-крючок ≤60 символов
status: draft|ready   # ready = прошёл чек-лист, можно публиковать
target: test|@libmdbx # test = тестовая группа, @libmdbx = боевой канал
cta: <один из §2>     # обязателен
---
```

## 6. Источники данных

- Открытое ПО: публичные коммиты, релизы, PR, issues, статистика контрибьюторов
  (без персональных данных), публичные тесты.
- Закрытая часть: агрегированные итоги спринтов (без исполнителей), результаты
  нагрузочных проверок (без чувствительных метрик), общие выводы экспериментов
  (без деталей реализации).

## 7. Рабочий процесс

1. Автор (docs) черновик → `.skynet/news/drafts/<id>.md`, `status: draft`.
2. Проверка по чек-листу (§8); при соответствии — `status: ready`, выбор
   `target`.
3. Координатор/конвейер TASK-32 перемещает готовый драфт на ветку
   `skynet-news/drafts/`; после успешной публикации — `status: posted`
   (коммит-маркер).
4. Один пост — один драфт; правки — правкой драфта до `posted`.

## 8. Чек-лист перед публикацией

- [ ] Нет чувствительных данных (см. §3)?
- [ ] Подчёркнут прогресс открытого кода и роль роя (§2)?
- [ ] Есть CTA из разрешённого списка (§2)?
- [ ] Длина поста ≤400 символов, заголовок ≤60?
- [ ] 3–5 тезисов + 1 инсайт + «Следующий шаг» (§4)?
- [ ] Frontmatter заполнен полностью (§5)?

## 9. Актуальные драфты

См. `${SKYNET_ROOT}/.skynet/news/drafts/` и ветку `skynet-news/drafts/`.
