# alice-consult-codex — консультации с внешним AI-агентом «Алиса» (Yandex AI Studio)

> Адаптация инструкции владельца (2026-09-22, составлена Алисой).
> Инструмент: `.skynet/tools/alice-consult.py` (OpenAI-SDK, Responses API).
> Ключ доступа предоставит владелец (env: `YANDEX_CLOUD_FOLDER`, `YANDEX_CLOUD_API_KEY`).

## Назначение

Агенты роя могут обращаться к внешней языковой модели Алисы (и другим моделям
Yandex AI Studio) за консультацией: анализ, рассуждение, генерация идей,
классификация, работа с кодом, поиск информации. Это дополняет мозг роя внешним
мнением и полезно для: креативной дивергенции (TASK-34 Vision), второго мнения
по ревью, исследований, разбора инцидентов.

## КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ (внешний сервис!)

Алиса — **внешний сервис Яндекса**. Распространяется disclosure-policy из
`issues-pr-codex.md` §0:
- НЕ отправлять: внутренние ключи/токены/пароли, фрагменты закрытого кода,
  конфиги, логи, дампы, данные о внутренних пайплайнах/метриках/архитектуре роя,
  персональные данные.
- Вопрос формулировать ОБОБЩЁННО (описание проблемы без чувствительных деталей),
  либо вымышленный аналог («представь систему X с такими характеристиками»).
- Данные обрабатываются на серверах РФ (152-ФЗ); логи запросов сохраняются —
  не светить sensitive.

## Когда использовать (маршрутизация)

| Тип | Модель (--route) | temp | reasoning |
|---|---|---|---|
| Классификация/триаж | `yandexgpt-5-lite` (classify) | 0.1 | low |
| Извлечение сущностей | `yandexgpt-5-lite` (extract) | 0.1 | low |
| Свободный диалог/поиск | `aliceai-llm` (dialogue/search) | 0.6 | — |
| Анализ/разбор | `yandexgpt-5.1` (analysis) | 0.4 | medium |
| Архитектура/проектирование | `yandexgpt-5.1` (design) | 0.5 | high |
| Код/длинные документы | `deepseek-v4-flash` (code) | 0.2 | medium |
| Генерация идей/брейншторм | `aliceai-llm` (brainstorm) | 0.9 | — |
| Оценка по критериям | `yandexgpt-5.1` (criteria) | 0.2 | medium |

Дефолт (без --route): `aliceai-llm`. Для structured output — `--json-schema`.

## Использование

```
python3 /sourcecraft/workspace/.skynet/tools/alice-consult.py --ask "<вопрос>"
python3 ... --ask "<код/анализ>" --route code
python3 ... --ask "<черновик идей>" --route brainstorm
python3 ... --ask "<текст>" --route classify --json-schema '{...}'
python3 ... --conversation "<conv_id>" --ask "<уточнение>"   # многошаговая консультация
python3 ... --self-test                                        # проверка ключа
```

## Правила для агентов

1. Консультироваться по делу: сначала собственный анализ, Алиса — как второе
   мнение/дополнительный взгляд, НЕ как замена исполнению.
2. Санитайзить вопрос (см. ограничение выше). Если вопрос содержит внутреннее —
   переформулировать обобщённо или спросить координатора.
3. Экономия: дешёвые модели для массового (Lite/Flash), дорогие (Pro/Alice) —
   только сложные задачи; `reasoning` включать по необходимости (low/medium/high).
4. Результат консультации фиксировать в отчёте/памяти: что спросили (обобщённо),
   что ответила Алиса, что взяли в работу. Проверять факты Алисы (она может
   ошибаться) — Gemba перед принятием.
5. Не гонять большие пакеты без нужды: стоимость токенов считается.
6. Ключ НЕ хранить в репо/файлах; только env.
