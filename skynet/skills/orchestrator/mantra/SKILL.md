# SKILL: Мантра (проактивный cyclic loop координатора, v2.2)

> Режим работы координатора, заданный владельцем (2026-09-24): непрерывный
> проактивный цикл без ожидания промпта. **ГЛАВНЫЙ ЗАКОН (владелец, 2026-09-24,
> крит. поправка): в Мантре НЕЛЬЗЯ ждать почту — максимум 1 секунда.
> Суть Мантры — не ждать, а совершенствоваться, повторяя мантру.**

## Ключевое отличие от Медитации

- **Медитация** — event-driven: вызывает `coordinator-step.sh`, который
  БЛОКИРУЕТ до события (waitmail, COORDINATOR_WAIT до 540с). Пауза между
  событиями — Improvement Tick.
- **Мантра** — proactive: НИКОГДА не блокирует больше 1с. Каждый проход —
  полный цикл самосовершенствования (Шаги 0-9), независимо от наличия почты.
  Письма обрабатываются если есть (быстрый чек ≤1с), но отсутствие писем —
  НЕ повод ждать: выполняется полный проактивный проход, затем цикл повторяется.

## Механизм цикла (обязательный)

```
loop {
  # быстрый чек почты ≤1с (НЕ блокировка!)
  rc = coordinator-step.sh 0.coordinator   # COORDINATOR_WAIT=1 (макс 1с)
  case rc in
    0)   MAIL      → обработать всю почту (Шаги 1-2) → continue (re-call)
    1)   NO-MAIL   → выполнить ПОЛНЫЙ проактивный проход (Шаги 2-9)
                     → continue (re-call, снова ≤1с)
    130) OWNER-CALL→ прочитать директиву владельца, выполнить,
                     ответить в МАКС, вернуться в цикл
    *)   UNEXPECTED→ диагностировать, залогировать, re-call
  esac
}
```

- Вызов: `BOARD_SILENT=1 COORDINATOR_WAIT=1 timeout 10 ./coordinator-step.sh 0.coordinator`.
- rc=1 (нет писем) — это НЕ пауза и НЕ «ждать»: немедленно полный проактивный
  проход (Шаги 2-9) и повторный вызов.
- **Запрещено** использовать COORDINATOR_WAIT>1 в Мантре. Длинная блокировка —
  это режим Медитации, не Мантры.
- Выход из цикла — ТОЛЬКО по явной инструкции владельца.

## Анти-паттерны (запрещено)

1. **Ждать почту дольше 1с.** В Мантре длинная блокировка запрещена — это
   режим Медитации. Если хочешь блокировать — это отдельный режим.
2. **Завершать ответ текстом** «цикл завершён / жду / перехожу к началу» без
   фактического повторного вызова. Последнее действие прохода — вызов утилиты.
3. **Ждать промпт** владельца между проходами.
4. **Плодить работу** без причины (идемпотентность §20): Шаг 5 — один элемент;
   но исследование/планирование/обучение/метрики (польза) всегда допустимы.
5. **Подменять агентов**: найденная работа делегируется (письмо+wake).
