# SKILL: Self-Monitoring (Level 4, оркестратор)

> Проверка себя на Retrospective + перед каждым Planning.

## Антипаттерны и контрмеры

| Антипаттерн | Симптом | Контрмера |
|---|---|---|
| Analysis paralysis | ST на тривиальных задачах | эвристика для повторяющихся |
| Meta-loop trap | анализ вместо работы | жёсткий таймбокс на анализ |
| Metric tunnel vision | оптимизация одной метрики | multi-metric review |
| Coordinator dominance | координатор вытесняет аналитик/менеджер | церемонии как точки переключения |
| Thrashing | >1 mid-sprint switch | фиксация состава на спринт |
| Memory bloat | >100 записей в памяти | очистка на Refinement |
| Silo effect | OBSERVATIONS не разобраны | Refinement при >5 pending |
| «Исполнение вместо координации» | координатор сам делает обычные задачи | делегировать агентам (протокол §13) |

## Принятие решений (MCP-sequential-thinking)

**Обязательно:** конкурирующие приоритеты epics/тасков; архитектура >1 модуля;
Kaizen-предложения; Sprint Goal при конфликте.
**Опционально:** рутинная координация, тривиальные блокеры, статусы.
Повтор задачи >3 раз → Kaizen (процесс слишком сложен).

## Эскалация к человеку

Новое ADR; изменение регламента Kaizen; sprint cancellation; ресурсный конфликт
вне пула; неуверенность после sequential-thinking. Формат: проблема + варианты +
рекомендация.

## Self-check перед Planning

- Есть Sprint Goal? — нет → сформулировать.
- Активная тройка соответствует? — нет → пересобрать.
- Module-locks назначены? — нет → назначить.
- WIP ≤ 3 соблюдён? — нет → отложить таски.
- Документация актуальна? — нет → планировать DS.

## Rollback-протокол

Откатывать если: сломана сборка target-платформы; падают ранее зелёные тесты
(не known-failure); рефакторинг изменил behaviour без intentional change.
Порядок: зафиксировать → таск FAILED → lock держать → revert/fix-forward →
фиксировать решение в memory (decision log) → паттерн >2 → Kaizen.
