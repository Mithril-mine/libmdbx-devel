# test-durability-strategy — стратегия тестирования (Level 2, для всех ролей)

> Источник: `agent_roles_skill.md §1.5/§6` + `functional-architecture.md §8`.
> Общий для всех ролей: выбор режима долговечности и транспорта напрямую
> определяет скорость CI.

## 1. Режимы записи на диск

| Режим | Поведение | Применимость |
|-------|-----------|--------------|
| `MDBX_SYNC_DURABLE` | flush данных + flush меты (fdatasync) каждый коммит | только crash-recovery / durability |
| `MDBX_NOMETASYNC` | данные флашатся, мета отложенно | редко нужен |
| `MDBX_SAFE_NOSYNC` | ничего не флашится, steady сохраняется | **дефолт для большинства тестов** (~10× быстрее) |
| `MDBX_UTTERLY_NOSYNC` | никаких флашей | если crash-recovery не тестируется вообще |

Принципы:
1. Самый лёгкий режим, если он не влияет на сценарий.
2. Риски пропуска регрессий устраняются длительными тестами с полным перебором.
3. Тесты durability/crash-recovery — отдельная категория, ночной прогон.

## 2. Транспорты для ускорения

| Платформа | Метод | Ограничения |
|-----------|-------|-------------|
| Linux | `/dev/shm` (tmpfs), `TMPDIR=/dev/shm` | без изменений кода |
| Windows | RAM-диск (ImDisk) или уменьшение объёма | настройка CI-раннера |
| Windows fallback | меньше операций/сценариев | компенсация длительными тестами на Linux |
| macOS | `/tmp` на APFS (RAM-cached) | достаточно для большинства |
| Android | неприменимо (NDK) | только SAFE_NOSYNC |

## 3. Quick / Full матрица

- **Quick**: safe_nosync + RAM-transport → каждый push.
- **Full**: durable + полный перебор → ночной прогон.

## 4. Правило для task-packages

Каждый тест в задаче явно указывает `DURABILITY-MODE` и `TRANSPORT`.
TE-Infra/PB контролируют, что лёгкие тесты не используют durable без причины.
