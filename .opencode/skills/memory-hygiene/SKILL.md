# memory-hygiene — гигиена общей памяти

> Общий принцип: **память — шпаргалка, документация в репозитории — источник истины.**
> Модуль памяти: [`skynet/MCP-shared-graph-memory`](../../../skynet/MCP-shared-graph-memory).

## Правила

1. **Память хранит указатели, не содержание.** ADR/регламенты/архитектура —
   в origin-tree (`docs/engineering/*.md`), в памяти — ссылка.
2. **Что хранить:** текущую цель/этап, активные цели спринта, WIP-статус,
   недавние решения, риски, бэклог улучшений, метрики, карту module-locks,
   наблюдения на рассмотрении.
3. **Что НЕ хранить:** содержимое ADR/регламентов, полный текст review,
   исходный код, контекст-пакеты, завершённые улучшения.
4. **Единственный писатель памяти — MCP-сервер.** Скрипты/агенты пишут
   наблюдения через MCP-вызовы, не правят файл БД напрямую.
5. **Гигиена:** периодическая очистка; устаревшие записи архивируются
   в документацию. Правило: **нет в памяти — нет в проекте** (незафиксированное
   решение не принято).

## Knowledge-harvest (сбор знаний)

После крупной работы фиксируй «уроки»: инварианты, ловушки именования, связи
S-подсистем (см. [`docs/engineering/libmdbx-invariants.md`](../../../docs/engineering/libmdbx-invariants.md)) —
как наблюдение или как предложение по обновлению профиля/навыка.
